# 教师培训网站设计优化方案

日期：2026-09-27。性质：生产站视觉检查、代码核对与实施建议。已完成六个关键页面/状态的桌面与手机宽度检查；登录后的成果列表与生成流程未覆盖。

## 依据与边界

- 使用当天 17:33 更新的共享 `frontend-design/SKILL.md`，重点采用真实教师任务、明确的文字层级、减少装饰性标签、集中一个视觉记忆点等原则。
- 使用共享 `ui-ux-pro-max` 的可读性、触控与响应式规则。其自动设计系统检索误配了定价页结构，未采用该结构、配色与外部字体建议。
- 内置浏览器与 Computer Use 初始化失败后，用户明确要求继续视觉检查，本轮使用备用 Playwright 访问 `https://ai.teachailab.com/`。
- 视口为桌面 1440×900、手机宽度 390×844。手机部分是 Chromium 视口模拟，不是真机 Safari 或虚拟键盘测试。
- 本次共保留 13 张逐张打开核对的截图，包含六个页面/状态与一次素材筛选操作；见[按步骤排列的截图与结论](2026-09-27-design-evidence/README.md)。未使用旧截图。初始工具页仍在加载的截图已用加载完成后的截图替换，未把短暂 Logo 空白当作故障。
- 实际页面文案与部分代码默认值不同，建议以本次截图中的生产文案为准。未登录账号、未提交生成请求，未修改网站源码、生产服务或账号数据。
- 本报告不是完整无障碍认证。检查了可见布局、实际字号/颜色、少量控件尺寸和一次键盘焦点；未覆盖屏幕阅读器、200% 缩放、真实触控及登录后流程。

## 视觉检查后的结论

优先级调整为：手机教学设计工作台 → 工具/素材可读性与筛选 → 桌面成员目录 → 首页局部精简。

1. **首页整体可用，降低改版优先级。** 桌面第一排任务卡从约 y=531px 开始，手机第一排约 y=469px，均能直接发现真实任务。无需为追求“设计感”重做首屏。初次访问出现的更新提示确实覆盖桌面左下方任务区，宜改为更紧凑的提示。
2. **教学设计手机端应先改。** 首个任务输入框位于约 y=715px，生成按钮位于约 y=1189px；用户先经过成员介绍、状态/步骤、备课本与模型标识、项目提示、重复开场说明。建议把未设置项目折叠为“复用教学背景（可选）”，合并成员说明，输入框前移，主要表单字号增至 16px。验收目标：390×844 首屏完整展示任务输入框，并能清楚找到后续操作；无需机械追求所有字段都塞进首屏。
3. **工具/素材小字已由运行时确认。** 两页卡片正文都是 12.7px；工具说明是 10.5px；两页手机筛选按钮高 36px。工具正文与背景的实际颜色对应约 4.36:1，说明约 3.30:1。字号、颜色与触控优化均保留为高优先级。
4. **成员目录只需适度压缩。** 桌面首屏的大幅肖像把动作按钮推到折叠线下方；手机卡片已经较紧凑，首排能显示“开始协作”。重点压缩桌面肖像高度和顶部说明，而不是全端统一缩小人物或取消人物设定。
5. **发现两处文案/可发现性问题。** 工具页提示“单项核对日期见卡片”，实际卡片没有日期；素材页手机布局隐藏了“在新窗口打开官网”说明。筛选后部分选中分类会被横向可视区裁切，应让选中项完整进入视野并提供更多分类提示。
6. **备课本仅能评价未登录态。** 未登录页面及账户弹窗布局正常；中央大空白可以增加简短功能说明和“先去生成一份教案”入口。实际成果列表、编辑、导出、保存与跨设备恢复未检查，不据此要求改造其布局。

补充技术观察：浏览器多次记录 `/api/analytics` 返回 HTTP 400，页面主流程仍可浏览。仅记录此现象，尚未诊断原因，不把它当成视觉问题或据此声称统计整体失效。

## 总体方向

保留现有冷灰背景、朱红品牌色、系统中文字体，以及数字教研团队和备课本的产品识别。用“今天要完成的教学成果”贯穿首页、成员目录、任务简报、结果编辑和保存，优先优化使用成本。

不要仅因新版技能将某些元素列为常见模板特征，就删除已有品牌色或人物资产。现有任务入口、按部门渐进展示、公开简报预览、参数折叠、教师核验和草稿恢复都是可继续使用的基础。

## 建议的设计基础

- 背景 `#F3F6F8`，面板 `#FFFFFF`，标题 `#17212B`，正文 `#3D4A57`，品牌行动 `#B64235`，结构与链接 `#245B78`。这些是对现有设计的归拢，最终仍需按各用途验证对比度。
- 继续用系统中文无衬线字体；正文建议 16px，卡片正文至少 14px，辅助信息 12–13px。等宽字体仅用于确实需要对齐的数值。
- 左对齐；间距按 8 / 12 / 16 / 24 / 32 / 48px 收敛；表单、卡片、弹层分别采用合适圆角，不追求全部一致。
- 视觉记忆点集中在“数字教研伙伴与可编辑教学成果”；其他页面保持安静。首页不新增纯装饰的统计面板或在线状态。
- 动效以打开、折叠、保存反馈为主，继续尊重减少动态效果设置。

## 实施顺序

1. 已完成：六个关键页面/状态的视觉基线与实际样式核对。登录后成果列表仍是明确的覆盖缺口。
2. 第一批：手机教学设计页的说明层级、项目折叠、表单字号与输入位置；保持原数据字段和生成逻辑。
3. 第二批：工具/素材页字号、颜色、触控、选中分类可见性；修正文案与实际卡片不一致。
4. 第三批：适度压缩桌面成员目录，局部精简首页，将验证过的组件推广并随改动合并重复 CSS。
5. 运行 `npm run check`，补充受影响页面的键盘和响应式检查。检查通过后再讨论发布。

## 模型与节省用量

本节推荐的是执行网站优化的开发模型，不是网站面向教师调用的内容生成模型。

**单模型方案：GPT-6 Sol，Medium，Standard 速度。** 这是结合本项目多页面 CSS 覆盖、响应式布局和既有交互作出的建议。官方将 Sol 定位于日常与复杂编码，并建议从 Medium 开始。无需一开始使用 Max / Ultra。

**更低费用方案：** 在设计规格已经确定后，用 GPT-6 Luna High 做单页字号、间距、文案与少量组件状态修改；跨页布局或不明原因的样式覆盖交回 Sol。这里的分阶段选择不要求并行子智能体。若当前模型选择器没有 GPT-6 Sol，可先使用仍在过渡期提供的 GPT-5.6 Sol；不能从文档推断当前账号已获得某个型号。

官方 API Standard 短上下文价格，单位美元 / 百万 token，未缓存输入 / 输出分别为：

| 模型 | 输入 | 输出 | 本任务用途 |
| --- | ---: | ---: | --- |
| GPT-6 Luna | 0.10 | 0.50 | 清楚、局部、可重复的小改动 |
| GPT-6 Sol | 2.00 | 10.00 | 本轮主要实施与回归处理 |
| GPT-6 Astra | 10.00 | 50.00 | 复杂审查或难题升级，不必全程使用 |

同等计费 token 数量下，Sol 的上述输入/输出单价均比 Astra 低 80%；这不等于任务会少用 80% token，也不是 ChatGPT 订阅额度的换算。总消耗还取决于上下文、推理、工具输出与返工。实际可用模型和收费以账号及执行时页面为准。

控制 token 的具体方式：每批只处理 1–2 个关联页面，引用本方案与必要代码，使用局部补丁，不输出整份 HTML；每批一次相关验证，通过后停止重复检查。先明确验收结果，再执行局部修改，比持续提出宽泛的“更高级一点”更容易减少返工。
