## 历史清理工具：未来由负责人另行安排

脚本：`scripts/clean-analytics-personal-fields.mjs`。

它只处理 `firestore_documents.collection_name = 'analytics_events'`，同时删除 `fields_json` 顶层和 `raw_json.fields` 内的 `userEmail / userPhone / userName / userSchool`。字段即使是空字符串或 null，也会删除。保留 uid、动作、原事件时间以及其他集合和用户资料。

安全约束：

- 必须明确指定 `--dry-run`（只检查）或 `--execute`（真正执行），不带参数不会修改数据。
- 只允许本机数据库地址，且必须显式提供独立的 `ANALYTICS_CLEANUP_DB_*` 配置；不加载 `.env`，不复用生产默认数据库。
- 执行必须提供新的绝对备份目录；拒绝覆盖已有目录，拒绝备份放在项目目录内。操作者还须选择不由网站公开提供的目录。
- 先备份全部目标事件到 `analytics-events.jsonl`，生成带数量和 SHA-256（文件完整性校验值）的 `manifest.json`，核对文件并确认落盘，再发出第一次修改。
- 备份目录权限为 700，文件为 600（仅当前系统账号可读写）；备份仍含原始个人资料，不可上传版本库、网站或普通共享盘。
- 每次读取 250 条，避免把整个集合装入内存；整轮修改使用一个事务（要么全部完成，要么全部撤回），要求数据表为 InnoDB（支持失败撤回的表类型）。
- 执行时锁住目标记录，防止备份与清理之间发生变化；可能短暂阻塞新统计写入。未来正式执行应安排低峰时段，先部署停止写入四项资料的服务端修复，再执行清理。
- 校验残留为零才提交；清理期间出错则撤回。重新执行不重复删除其他数据。
- 日志只输出数量，不输出用户资料。连接中断等异常后，应再次 `--dry-run` 核对实际状态，不能仅凭终端文字推断成功。

由操作者在隔离测试环境或以后获授权的数据库所在主机上，安全配置以下环境变量（密码不写入命令历史、报告或代码）：

```text
ANALYTICS_CLEANUP_DB_HOST=127.0.0.1
ANALYTICS_CLEANUP_DB_PORT=<端口>
ANALYTICS_CLEANUP_DB_NAME=<明确选择的数据库>
ANALYTICS_CLEANUP_DB_USER=<专用数据库账号>
ANALYTICS_CLEANUP_DB_PASSWORD=<通过安全方式注入>
```

操作顺序：

```bash
# 1. 只检查，记录受影响条数
node scripts/clean-analytics-personal-fields.mjs --dry-run

# 2. 另行获授权后执行：脚本先备份、验证成功，再清理
node scripts/clean-analytics-personal-fields.mjs --execute --backup-dir /非公开目录/新的统计备份目录

# 3. 再查一次，affected 应为 0
node scripts/clean-analytics-personal-fields.mjs --dry-run
```

输出中 `scanned` 是扫描记录数，`affected` 是至少含一个待删字段的记录数，`fields` 是每个字段涉及的记录数（两份副本合并去重），`changed` 是本次修改数。备份清单中的 `backup-verified` 只表示备份核验成功，不代表后续清理已提交。备份恢复由运维人员按清单核验后处理，本脚本不自动恢复个人资料。

## 按天预聚合评估（未实施）

现状：腾讯路径每次把全部事件读进内存，按日期筛选并截取最近 6000 条；Firebase 旧路径先由数据库筛选日期，再限 6000 条。截断会漏算，腾讯路径还随历史积累增加内存与读取耗时。本轮保持现有上限与提醒，没有悄悄改变统计口径。

建议第五阶段只在当前 MariaDB 路径建设：
