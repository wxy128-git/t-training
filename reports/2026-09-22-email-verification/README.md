## 用户现在会看到什么

1. 新注册必须填写能收信的邮箱，不能再用手机号注册。创建账号后自动发送验证邮件；未完成验证，页面停留在邮箱完善窗口。
2. 已有手机号账号仍可用原手机号和密码登录，随后填写自己的邮箱。点击邮件中的链接并回到网站确认后，再使用功能。
3. 绑定保留原账号编号、学校、手机号、加入日期、云端作品和按账号保存的本机草稿。绑定完成后使用邮箱和原密码登录，忘记密码时向该邮箱发送重置链接。
4. 邮箱可在验证前修正；支持重发倒计时、再次输入密码核验、验证状态确认和退出换号。仅发送邮件不代表已验证。
5. 用户明确暂缓人工恢复。因此未开通人工工单，也不需要站点负责人提供收件邮箱。已经无法登录的旧手机号账号不在本次自动绑定范围内。

## 实现范围

- 浏览器与 API 共用 `js/account-policy.js`，只有真实邮箱且 Firebase Auth 返回 `emailVerified: true` 才允许使用受保护功能。个人资料或请求体中的同名字段不能授予权限。
- 全部 13 个应用页面加入 `js/email-gate.js`。原生弹窗阻止背景交互，支持键盘焦点循环；备课本在验证前不发送资料加载请求。
- 认证代理新增 `verify-email` / `email-status`：新邮箱账号使用 `VERIFY_EMAIL`；旧手机号或填错邮箱使用 `VERIFY_AND_CHANGE_EMAIL`，验证后由 Firebase 更新同一个 UID，不创建替代账号。
- 60 秒重发间隔、每账号每 10 分钟 6 次及请求限流；并发发送共用同一个冷却窗口。Firebase 明确拒绝时允许修正后重试，网络结果不明时保留冷却。计数在服务进程内，重启或多实例会重置 / 分散计数，不声称全局硬限额。
- 智能体、备课本、邮箱登记、管理员接口及统计管理接口重新检查 Firebase Auth 状态；Firestore Rules 也限制浏览器直连。未验证者仅可维护自己的基本资料以完成绑定；公开内容仍可由访客浏览。
- 验证后更新代理会话并尝试刷新浏览器 SDK 声明；旧凭据失效时提示用新邮箱和原密码重新登录。慢速认证响应不能覆盖已切换的账号或把已验证状态恢复为未验证。
- 资源版本 `20260922-email-required`，Service Worker `20260922-v21`。腾讯云打包器把共享账号策略同时包含在静态文件与 API 包中。
