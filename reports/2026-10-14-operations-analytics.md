## 统计范围

- 独立的 OperationsAnalytics 浏览器通道只提交固定页面 / 伙伴 / 案例计数。单页首次可见时记录一次打开，切回页面不重复；不设置 Cookie、账号令牌、访客或会话标识，不发送来源地址及查询 / hash 内容。
- 模型进入调用阶段后的成功、失败及成功耗时由 `/api/agent` 的服务端钩子累计；输出经过完整性校验并发送完成标记后计成功，部分输出或中断计失败。前端原有成功 / 失败上报不进入新计数，避免重复。研究伙伴也在固定白名单内。
- 新成果成功写入备课本后由服务器计数；重命名、删除、失败保存不算新保存。现存成果根据作品创建时间在 SQL 内汇总，分析代码不读取标题、正文、输入或拥有者；它不是历史保存总次数，已删除成果不计。
- 两表只存每日固定动作、功能、固定目标编号、次数和累计成功耗时，以及首次启用时间；无个人事件、身份或自由文字。旧 Analytics.track、两个后端旧 track、研究同意逻辑保持关闭，既有历史数据不改、不清理。
- 无访客标识，因此独立访客 / 活跃人数、个人明细和跨行为漏斗不提供。新后台十项指标、每日趋势和固定伙伴 / 案例排名仅显示汇总。

## 数据口径和故障

- `T_TRAINING_OPERATIONS_ANALYTICS=1` 才启用；默认关闭。首次初始化新增 InnoDB 表，原子递增支持并发，重复初始化不重置开始时间。生产已显式开启独立运营开关，并初始化两张汇总表。
- 首次启用前的访问 / 生成不可补回，显示“—”。启用当天为部分时段，后续无记录显示 0；后台说明统计覆盖范围。注册和现存成果可从业务记录统计。
- 管理员凭证才能查看汇总；公开浏览器接口只接收允许的访问 / 功能计数，不接受模型成功或保存伪造。固定维度限制表的增长；日期与计数由服务器确定，跨站来源被拒绝。
- 浏览器错误不影响页面，统计写入放在后台任务中；保存钩子故障不影响成功业务，运营表初始化失败也不阻断 API 启动。汇总读取失败显示错误，不返回假零。
- 页面计数是浏览器上报的打开次数，不等于独立人数，也不是防机器人审计指标。未来若配置停用再启用，需要标明停用空档；本轮不自动把此类空档当作真实零。
